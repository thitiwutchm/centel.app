# centel.app — วางแผนจ่ายบิล

เว็บแอปสำหรับวางแผนการจ่ายค่าบัตรเครดิต ค่าน้ำ ค่าไฟ และบิลรายเดือนอื่นๆ ออกแบบสำหรับ iPhone
ติดตั้งลงหน้าจอโฮมได้ (PWA) ใช้งานออฟไลน์ได้ และเก็บข้อมูลไว้ในเครื่องเท่านั้น

## ความสามารถ

- เพิ่มบิลแบบ **ทุกเดือน**, **ผ่อนเป็นงวด** (แสดงงวดที่ x/y) หรือ **ครั้งเดียว**
- บิล **ยอดไม่แน่นอน** (บัตรเครดิต ค่าน้ำ ค่าไฟ) กรอกยอดจริงได้ในแต่ละเดือน
- หน้า **เดือนนี้**: ยอดรวม จ่ายแล้ว คงเหลือ, ยอดที่ต้องเตรียมช่วงวันที่ 1–15 และ 16–สิ้นเดือน, แจ้งเตือนบิลเลยกำหนด/ใกล้ครบกำหนด
- แตะวงกลมเพื่อทำเครื่องหมาย **จ่ายแล้ว**
- **ปฏิทิน** รายเดือนแสดงสถานะบิลแต่ละวัน
- **เตือนผ่านแอปปฏิทิน iPhone**: สร้างไฟล์ .ics พร้อมเสียงเตือนล่วงหน้า
- ตัวเลขแจ้งเตือนบนไอคอนแอป (iOS 16.4+ เมื่อติดตั้งที่หน้าจอโฮม)
- สำรอง/นำเข้าข้อมูลเป็น JSON, รองรับโหมดมืด

### รายรับรายจ่าย (แนวทางแอป Money Lover, ใช้ชุดสีเดิม)

แท็บล่างแบบแคปซูลลอย: **หน้าหลัก · รายการ · บิล · งบประมาณ · บัญชี** และปุ่ม **＋ เพิ่มรายการ** ลอยมุมขวาล่าง

- **หน้าหลัก**: ยอดเงินรวม (กดรูปตาเพื่อซ่อน), ค้นหา, กระดิ่งแจ้งเตือน (บิลใกล้ครบกำหนด/งบเกิน), กระเป๋าเงินของฉัน,
  บิลที่ต้องจ่ายเดือนนี้, รายงานเดือนนี้ (กราฟสะสมรายจ่าย/รายรับ เทียบค่าเฉลี่ย 3 เดือนก่อน), ข้อมูลเชิงลึกหมวดที่ใช้มากสุด, รายการล่าสุด
- **รายการ**: เลือกกระเป๋าเงิน (หรือยอดรวม), แท็บเดือนย้อนหลัง · เดือนก่อน · เดือนนี้ · อนาคต, ยอดยกมา/ยอดคงเหลือ,
  รายการจัดกลุ่มตามวัน, ค้นหา, รายงานตามหมวดหมู่, ส่งออก CSV · แท็บอนาคตแสดงบิลที่กำลังจะถึงด้วย
- **บิล**: หน้าวางแผนจ่ายบิลเดิม (เดือนนี้ / ปฏิทิน / บิลทั้งหมด)
- **งบประมาณ**: เกจครึ่งวงกลม "จำนวนที่ใช้ได้", งบแต่ละหมวดพร้อมเส้น "วันนี้", หน้ารายละเอียดมีกราฟใช้จริงสะสม เส้นงบ เส้นคาดการณ์
  และ ควรใช้ต่อวัน / คาดว่าจะใช้ทั้งเดือน / ใช้จริงเฉลี่ยต่อวัน
- **บัญชี**: จัดการกระเป๋าเงิน, เลือกกระเป๋าที่ใช้บันทึกเมื่อกด "จ่ายแล้ว" ที่บิล, การตั้งค่าเดิมทั้งหมด

กด "จ่ายแล้ว" ที่บิลจะสร้างรายการรายจ่ายให้อัตโนมัติ (ยกเลิกแล้วรายการจะถูกลบ) ข้อมูลส่วนนี้เก็บที่ localStorage `centel.money.v1`
แยกจาก `billplanner.v1` เพื่อไม่ให้ ThemeA/ThemeB เขียนทับ

### บัญชีคู่ (รายจ่ายส่วนตัว / ร่วมกัน)

ตาม PRD "couple expense app" เมื่อเข้าสู่ระบบ (บัญชี → เข้าสู่ระบบ / สมัครสมาชิก) ข้อมูลรายรับรายจ่ายจะซิงก์กับเซิร์ฟเวอร์ใน `server/`

- แต่ละคนมีบัญชีของตัวเอง เชื่อมกันด้วยรหัสเชิญ 6 ตัว (อายุ 7 วัน)
- รายจ่ายส่วนตัวเห็นเฉพาะเจ้าของ บังคับที่ฐานข้อมูลด้วย Row Level Security ไม่ใช่แค่ในหน้าจอ
- รายจ่ายร่วม: ระบุผู้จ่าย ยอดรวม และส่วนของแต่ละคน (เริ่มต้น 50/50) แล้วส่งให้อีกฝ่าย **อนุมัติ/ปฏิเสธ** เท่านั้น (แก้ไขไม่ได้)
  ถูกปฏิเสธ → ผู้สร้างแก้แล้วส่งใหม่ (เก็บประวัติทุกครั้ง) · รออนุมัติยังไม่นับยอด · อนุมัติแล้วจึงเกิดยอดค้างคืนตามสัดส่วน
- ยอดค้างคืนมีสถานะ ยังไม่ชำระ/ชำระแล้ว แยกจากการอนุมัติ การคืนเงินย้ายเงินระหว่างกระเป๋าแต่ไม่นับเป็นรายจ่ายซ้ำ
- งบส่วนตัวนับส่วนของฉัน งบร่วมนับยอดรวมทั้งบิลที่อนุมัติแล้ว เตือนที่ 80% และเมื่อเกิน 100%
- แนบสลิปด้วยกล้องหรือเลือกรูป เก็บใน bucket แบบ private (เปิดดูผ่านลิงก์ชั่วคราว 5 นาที) และให้ Claude อ่านวันที่ ยอด ร้านค้า
  และหมวดหมู่ สลิปโอนเงินที่ไม่ระบุวัตถุประสงค์จะเป็น "รอตรวจสอบ" ให้ผู้ใช้เลือกเอง · สลิปที่เลขอ้างอิงซ้ำจะถามก่อนบันทึก
- ไม่ได้เข้าสู่ระบบ แอปทำงานแบบเดิมจาก localStorage ทั้งหมด (รายการบิลยังเก็บในเครื่องเสมอ)

เซิร์ฟเวอร์ (`server/`, Node + PostgreSQL): `Caddyfile` ส่งต่อ `/api/*` ไปที่บริการ `api` ผ่าน private network ของ Railway
(`$API_UPSTREAM`, ค่าเริ่มต้น `api.railway.internal:8080`) ตัวแปรของบริการ `api`: `DATABASE_URL`, `PORT=8080`,
ค่าของ bucket (`BUCKET`, `ENDPOINT`, `REGION`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`) และ `ANTHROPIC_API_KEY` สำหรับอ่านสลิป
(ไม่ใส่ก็ได้ แอปจะแนบรูปโดยไม่อ่านอัตโนมัติ; เลือกโมเดลได้ด้วย `RECEIPT_MODEL`) คีย์อยู่ที่เซิร์ฟเวอร์เท่านั้น ไม่ถูกส่งไปที่หน้าเว็บ

เข้าสู่ระบบด้วย Google: ใส่ `GOOGLE_CLIENT_ID` (OAuth Web client ตัวเดียวกับที่ใช้ดึงบิลจาก Gmail) ที่บริการ `api`
เซิร์ฟเวอร์ตรวจ ID token กับกุญแจของ Google เอง ครั้งแรกจะสร้างบัญชีใหม่ หรือเชื่อมกับบัญชีอีเมล/รหัสผ่านเดิมที่อีเมลตรงกัน
(Google ยืนยันอีเมลแล้ว) ถ้าไม่ได้ตั้งค่าไว้ ปุ่ม Google จะไม่แสดง และการเข้าสู่ระบบด้วยอีเมลยังใช้ได้ตามเดิม

ทดสอบเซิร์ฟเวอร์: `cd server && npm ci && DATABASE_URL=... GOOGLE_CLIENT_ID=test-client GOOGLE_CERTS_URL=http://localhost:3998/ npm start`
แล้วอีกหน้าต่าง `DATABASE_URL=... npm test`

## ใช้งานบน iPhone

1. เปิดเว็บด้วย Safari
2. แตะปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**

## Deploy

ไฟล์ทั้งหมดเป็น static (ไม่มีขั้นตอน build)

- **Railway** (โดเมน centel.app): Railway build จาก `Dockerfile` ซึ่งเสิร์ฟไฟล์ด้วย Caddy ตาม `Caddyfile`
  (ฟังที่ `$PORT`) และ deploy ใหม่อัตโนมัติเมื่อ push เข้า `main`
- **GitHub Pages** (สำรอง): `.github/workflows/pages.yml` จะ deploy เมื่อ push เข้า `main`

ทดสอบในเครื่อง: `npx http-server .` แล้วเปิด http://localhost:8080

## ดึงบิลค่าโทรศัพท์จาก Gmail

แท็บ บิล หรือ บัญชี → "📧 ดึงบิลค่าโทรศัพท์จาก Gmail" ค้นหาใบแจ้งค่าบริการจาก AIS, True, dtac, 3BB, NT ย้อนหลัง 4 เดือน
แล้วเติมยอดและวันครบกำหนดเข้าบิลค่าโทรศัพท์ (สร้างบิลใหม่ให้ถ้ายังไม่มี แยกตามผู้ให้บริการ + หมายเลข)
เบราว์เซอร์อ่าน Gmail โดยตรงด้วยสิทธิ์ `gmail.readonly` แบบ access token อายุ 1 ชั่วโมง (Google Identity Services) ไม่มีอีเมลผ่านเซิร์ฟเวอร์ของเรา
ถ้าเนื้ออีเมลไม่มียอด แอปจะอ่านจาก PDF แนบ (pdf.js จาก cdnjs) และเก็บ PDF ไว้กับบิลเดือนนั้น ยอดใน PDF ที่ใส่รหัสผ่านจะอ่านไม่ได้ ต้องกรอกยอดเอง

แต่ละบิลแต่ละเดือนแนบ PDF หรือรูปใบแจ้งหนี้ได้ (กดที่บิล → ใบแจ้งหนี้) ไฟล์เก็บใน IndexedDB ของเครื่อง (`centel.files`) ไม่รวมในไฟล์สำรอง JSON

ตั้งค่าครั้งเดียว:
1. Google Cloud Console → สร้างโปรเจกต์ → APIs & Services → Library → เปิด **Gmail API**
2. OAuth consent screen (Google Auth Platform) → External → ใส่ชื่อแอปและอีเมล → Data access เพิ่ม scope `.../auth/gmail.readonly` → Audience เพิ่มอีเมลตัวเองเป็น Test user
3. Clients → Create client → **Web application** → Authorized JavaScript origins: `https://centel.app` และ `https://www.centel.app` (ไม่ต้องใส่ redirect URI)
4. นำ Client ID (`….apps.googleusercontent.com`) ไปตั้งเป็นตัวแปร `GOOGLE_CLIENT_ID` ของ service `web` บน Railway (Caddyfile ส่งให้หน้าเว็บผ่าน `/api/config`)

## ThemeA (ดีไซน์สไตล์ Apple)

`themea/` คือหน้าตาแบบ Apple ของแอปเดียวกัน เปิดที่ `/themea/` ใช้ข้อมูลชุดเดียวกับหน้าหลัก (localStorage `billplanner.v1`)
แนวทาง: สีระบบ iOS, หัวข้อใหญ่ที่ย่อเข้าแถบโปร่งแสง, หน้าต่างล่างลากปิดได้ด้วยแอนิเมชันสปริง, รองรับลดการเคลื่อนไหว/ความโปร่งใส

## ThemeB (ดีไซน์ทางเลือก)

`themeb/` คือหน้าตาแบบที่สองของแอปเดียวกัน เปิดที่ `/themeb/` ใช้ข้อมูลชุดเดียวกับหน้าหลัก (localStorage `billplanner.v1`)
แนวทาง: สูตร "raycast" จาก web-design-engineer skill — พื้นเทาเข้ม การ์ดกระจกโปร่งแสงบนแสงไล่สีอุ่น สีแดง #FF6363 เฉพาะปุ่มสำคัญ จุดสีประจำหมวด ชิปตัวเลขแบบปุ่มคีย์บอร์ด
ฟอนต์ IBM Plex Sans Thai, Inter Tight, JetBrains Mono ฝังไว้ใน `themeb/fonts/` (OFL)
